## Day 2 — Noor ID Layout (2026-11-10)

- **Problem:** copy/print shops need a quick way to place supplied document images on a print sheet without guessing physical card sizes.
- **Research:** reviewed the public READMEs for [Photo ID Creator](https://github.com/dpar39/ppp), [Idify](https://github.com/zhbhun/idify) and [Passport Photo Generator](https://github.com/rizwansoaib/passport-photo-generator). Both modules passed `py_compile`; CLI help ran.

No interactive Windows desktop GUI session, physical printer, manual paper reload, printer driver scaling, or actual front/back registration test was performed. GitHub Actions passed all four core-test jobs: Windows and Ubuntu on Python 3.10 and 3.12. No screenshot, Windows executable or release is claimed.

## Day 5 — Noor PDF Deskewer (2026-11-13)

- **Problem:** scanned PDFs can contain pages rotated a few degrees, causing hard-to-read or awkwardly printed documents.
- **Alternatives reviewed:** OCRmyPDF offers `--deskew` within an OCR/image-processing pipeline; `sbrunner/deskew` estimates skew for images; `unpaper` processes scanned sheets and offers deskew/cleanup. Noor PDF Deskewer focuses on an offline PDF interface with per-page estimates and manual correction, without requiring OCR.
- **Implemented:** Python core, Tkinter GUI and CLI; PDF page rendering with PDFium; projection-profile angle estimator for slight skew; per-page manual adjustment and preview; same-size page rotation without intentional edge clipping; batch PDF export with source preservation; safe temporary handling; limits for DPI, page count, page dimensions and correction angles; Windows install and rasterization tradeoff documentation.
- **Tests performed:** seven local `unittest` tests passed with Python 3.12, Pillow, NumPy, pypdf and pypdfium2. Covered known positive/negative synthetic skew, near-level and blank pages, correction direction, white-corner fill and unchanged page canvas, multi-page rasterized PDF output/page dimensions, measured skew reduction, mismatch angles, invalid PDF and source overwrite protection. Both modules passed `py_compile`; CLI help ran.

Output rasterizes pages, so pre-existing text/vector layers, annotations, signatures, links, metadata and bookmarks are not preserved.

## Day 8 — Noor PDF Page Reorganizer (2026-11-16)

- **Problem:** a small print/copy workflow needs a quick way to change page sequence, correct right-angle orientation, remove extras or extract selected pages from a single PDF without changing the source.
- **Alternatives reviewed:** PDF Arranger offers a broader graphical merge/split/crop/rearrange interface; PDFsam Basic provides offline rotation/extraction alongside merge, split, mix and insert; pypdf's official documentation describes right-angle page rotation and page-object export. This project is a compact single-document workflow with selected-page preview, direct page-sequence CLI syntax and local source-preserving output. It is not claimed to be unique or a replacement for full PDF editors. Sources: [PDF Arranger](https://github.com/pdfarranger/pdfarranger), [PDFsam Basic](https://pdfsam.org/pdfsam-basic/), [pypdf rotation guidance](https://pypdf.readthedocs.io/en/stable/user/cropping-and-transforming.html).
- **Implemented:** pypdf core, PDFium page preview and Tkinter GUI, plus CLI; one-based page order/range parser; reorder, remove, extract, and clockwise 90°/180°/270° page rotation; mixed MediaBox dimensions; corrupt/encrypted/non-right-angle rotation validation; 250 MB and 1,000-page input limits; output path/source collision protection and unique temporary-file export; Unicode paths. Page content remains PDF objects rather than rasterized images. Documentation warns that bookmarks, forms, signatures and other document-level features may not survive a rewrite.
- **Tests performed:** 11 local `unittest` cases passed with Python 3.12.3, pypdf 6.21.4, pypdfium2 4.30.0, Pillow 13.0.0 and ReportLab 5.1.0. Covered one-based range parsing, mixed page sizes, text-content retention, reorder/extract, page rotations including existing `/Rotate`, PDFium rendering, invalid plans/rotations, corrupt and password-protected inputs, Unicode paths, overwrite/source protection and preservation of source bytes. Both modules passed `py_compile`, CLI help ran, and an end-to-end CLI test reordered/extracted two of three pages, applied rotation and confirmed source bytes unchanged.
- **Not tested:** the GUI was not launched because Tkinter is unavailable in this Linux sandbox. No interactive Windows desktop use, physical scanner/printer test, build of a Windows executable/installer or release was performed. CI runs the core tests only; no GUI or hardware behavior is claimed.
- **Status:** source published at https://github.com/collodev21/noor-pdf-page-reorganizer; all four GitHub Actions core-test jobs passed (Windows and Ubuntu, Python 3.10 and 3.12). Central portfolio and roadmap updated. CI run: https://github.com/collodev21/noor-pdf-page-reorganizer/actions/runs/43967163016.

## Day 9 — Noor Local OCR Assistant (2026-11-17)

- **Problem:** scanned PDFs and images are not searchable unless recognized text is added or extracted. This workflow needs a small local-only path that makes the external OCR engine and language-data requirements visible.
- **Alternatives reviewed:** Tesseract is a local OCR engine that supports text, searchable PDF and invisible-text PDF output, but its project does not include a GUI. NAPS2 is a fuller desktop scanner/PDF application with OCR and language setup. OCRmyPDF is a mature Tesseract-based PDF workflow that integrates OCR layers into existing PDFs and handles many PDF edge cases. This project intentionally offers a smaller single-file workflow with engine/language readiness and either a searchable PDF or page-separated text; it does not claim to replace those tools. Sources: [Tesseract project](https://github.com/tesseract-ocr/tesseract), [Tesseract searchable-PDF usage](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html), [NAPS2 OCR guide](https://www.naps2.com/doc/ocr), [OCRmyPDF introduction](https://ocrmypdf.readthedocs.io/en/latest/introduction.html).
- **Implemented:** standalone Python/Tkinter GUI and CLI for one PDF or still image at a time; local Tesseract backend status and installed-language check; one/multiple language codes such as `fra+ara`; searchable PDF or UTF-8 page-labeled text; configurable 150–400 DPI; PDFium page rendering; source/output collision protection, unique temporary output, input/page/render safety caps and per-page timeout. A local temporary PNG is passed to Tesseract, with its DPI embedded. No network or upload path exists. The source is not changed. Searchable-PDF output rasterizes page visuals and does not preserve original vector data, links, bookmarks, forms, signatures, metadata or accessibility structure.
- **Tests performed:** 12 core `unittest` tests passed with mocked Tesseract calls; two real-engine integration tests passed with Tesseract 5.3.4 and English/French models. Environment: Python 3.12.3, Pillow 13.0.0, pypdf 7.1.0, pypdfium2 5.15.2 and pytesseract 0.3.13; installed Tesseract models were Arabic, English and French. `compileall` and CLI `--help` passed. Real end-to-end checks created searchable output from a synthetic image and a two-page image-only PDF; pypdf extracted the expected English text from the generated PDF, French CLI text extraction succeeded, and original source bytes remained unchanged. Unicode/Arabic file paths passed in unit tests. Arabic model availability was detected, but an experimental Arabic image did not yield consistently complete text; no Arabic recognition accuracy is claimed.
- **Not tested:** the Tkinter interface was not launched because Tkinter is unavailable in this Linux sandbox. No interactive Windows 10/11 GUI test, hardware scanner/printer test, Windows executable/installer build or release was performed. Windows CI validated the Python core without a Tesseract install; Linux CI installed Tesseract and ran the English OCR integration test. No GUI, physical-device or packaging behavior is claimed.
- **Status:** source published at https://github.com/collodev21/noor-local-ocr-assistant; all four GitHub Actions jobs passed on Windows and Ubuntu with Python 3.10 and 3.12. Central index and roadmap updated. CI run: https://github.com/collodev21/noor-local-ocr-assistant/actions/runs/44188276355.
